## 6. 其他注意事项

### 平台机制

- **YouTube 社区帖的链接**：据 2026 年的平台说明，帖子/简介里的可点击链接可能需要频道具备高级功能；如果没有，URL 会以纯文本显示。此时把 GitHub 地址放在视频简介和置顶评论里，并在帖子里写“link in description”。
- **YouTube 社区帖可用性**：不再要求 500/1000 订阅（以频道后台是否出现 Posts 标签为准）；但“为儿童打造”的频道、有社区规范处罚的频道不可用，德国地区也不可用。
- **X 链接**：主推文带链接可能略降推荐量，但开源项目需要转化，建议保留；可以把链接同时放在第一条回复里。
- **Facebook 外链**：外链帖触达通常低于纯图片帖；可以先用方图 + 故事发一条，再把链接放在第一条评论并置顶。
- **B 站视频**：海外访问可能慢或受限。GitHub 上的 Notebook/PDF 是主资源；如果要在 YouTube 长期运营，建议后续加英文字幕或做一版英文讲解。

### 语言与预期

- 所有英文文案都明确写了“taught in Chinese”。不要为了互动量隐瞒这一点，否则评论区会失控。
- 英文受众真正能用的是 Notebook、代码和 PDF；视频是给中文学习者的加分项。
- 如果之后做英文字幕，把 X 线程第 4 条和 YouTube 简介里的 “English subtitles are on my list” 改成 “English subtitles available”。

### 发布节奏

- 建议周二至周四，北京时间 21:00–23:00（美东上午）发 X / Facebook；YouTube 社区帖可放在周末。
- 三个平台不要同一分钟发；间隔 1–2 小时，方便分别回复评论。
- X 发完置顶；Facebook 发完把链接评论置顶；YouTube 置顶 GitHub 评论。
- 前 2 小时尽量回复每条评论，平台的早期互动会影响后续分发。

### 版权口径

- 说 “open-sourced the course materials” / “notebooks and PDFs are MIT licensed”，不要说 “the whole course is open source”。
- 视频是“free to watch on Bilibili”，版权保留；不要上传视频文件到 GitHub 或 YouTube 以外的地方。
- 如果有人问能不能商用：课件可以（MIT），视频不可以；培训/二次售卖课件可以，但建议保留作者与仓库链接。

### 追踪与复盘

- GitHub → Insights → Traffic 看 referrers、stars、clones；UTM 参数只影响外部统计，GitHub 本身不解析。
- 记录每个平台的首日数据（曝光、点击、stars），一周后对比；不要只看点赞。
- 如果某个平台反馈集中在“看不懂中文”，下一轮优先做英文字幕，而不是继续多发帖。

### 账号与主页

- X bio 加一句 “Open-source Python course ↓” 并放 GitHub 链接。
- Facebook 个人简介/主页简介放仓库链接。
- YouTube 频道链接里加 GitHub；如果做视频，频道简介写明“中文讲解，代码通用”。
- B 站视频简介/置顶评论补一句：“课件已开源：github.com/mashukui/python-beginner”。
